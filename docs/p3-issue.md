# P3 Issue 完整业务链路

日期：2026-11-06。对应 P3-01 至 P3-13；源码与验证产物均来自未提交工作区，不代表正式发布。机器证据见 [p3-result.json](validation/p3-result.json)。

## 1. 交付范围

Issue 应用服务位于 internal/app/issue，CLI、后续菜单和 MCP 可直接复用，不在服务层读取终端。已接通 list、view、create、edit、close、reopen、comment list／add、label list／add／remove、assignee add／remove。创建／编辑支持标题、正文或 UTF-8 文件、负责人、标签、里程碑和明确清空选项；非状态命令只接受单目标，关闭／重开接受 1–100 个去重后目标并保留首次次序。

读取使用 type=issues 并再次排除 PR，直接编号也校验资源类型。默认 page=1、limit=30，最多 100；--all 显式读取后续页。文本搜索在完整有界集合上计算不区分大小写的标题／正文子串，多个标签统一任一匹配；未知版本和无法无损表达的条件同样先完整读取再筛选分页。最多扫描 10000 项，重复页或超限报错，不输出看似完整的部分查询结果。未知版本允许读取和通用 API，业务写入要求命中七个已研究的精确版本。

所有写入均先准备不可变计划、展示实际目标与变更并默认 No；直接编号仍确认，--yes 只跳确认，不补参数。JSON、CI、无终端和 --no-interactive 不等待输入，缺目标／字段或未明确确认返回参数错误且无业务写入。

## 2. 写入边界与复审修复

计划只消费一次，提交前重新核对配置修订、账号身份和可观察的 Issue 前置状态；进程内按实例／账号／仓库串行。状态已满足时 skipped，批量逐项保留成功、失败、未知和未执行项；单项权限／目标错误继续，整体身份／网络或未知故障停止后续目标。主动取消以退出 130 优先，已发送请求仍保留 unknown，不声称回滚，也不自动重试。

1.27.3、28.3.0 使用原生负责人 POST／DELETE；五个旧版读取并计算增量后 PATCH 完整集合，预览明确覆盖风险，写前重读和写后核对只能降低可见冲突，不能保证其他进程的并发更新不丢失。标签使用原生增量增删；编辑标签以独立 PUT 执行，多步骤失败保留已完成步骤。

复审确认的四类问题及额外回读问题已处理：

| 问题 | 最终行为 | 验证 |
| --- | --- | --- |
| 创建时服务端遗漏负责人／标签等字段仍报告成功 | 创建一次后按返回编号读回全部显式字段；遗漏或读回失败保留已创建编号与成功步骤，报告部分完成，不重建。 | 合成服务覆盖完整、正文／负责人／标签遗漏及读回失败；真实创建字段链路另测。 |
| 多标签在服务端与本地分支语义不同 | 多标签完整有界扫描后按任一匹配计算，不因增加搜索条件或未知版本而改变。 | 合成服务模拟 AND；真实回归比较带搜索与不带搜索的结果。 |
| API 已接受写入后响应超限仅报普通失败 | 收到 2xx 后的响应、关闭、输出或文件提交失败统一报告 PARTIAL_FAILURE／退出 3，提示先查远端。未收到响应的已发送写入仍 unknown／退出 4。 | 单次写入和原始截断响应边界；真实 Gitea 的成功 POST＋响应上限。 |
| FIFO 输入卡住且不能响应中断 | 正文、原始请求与 multipart 共用普通文件检查；POSIX 非阻塞打开后再核对实际句柄，拒绝管道／设备／目录。 | 无写入者 FIFO 及底层非阻塞打开；普通文本／二进制和 multipart 正常链路。 |
| 写后回读失败清空最后已知资源 | 独立保存回读值，失败不擦除旧快照和编号；逐项 unknown 明确快照不是已确认写后状态。 | 合成服务在写入后返回 503，核对编号、旧状态和单次写入。 |

## 3. 交互与通用 API

缺少 Issue 编号时使用 Bubble Tea v1.3.10 选择器，Space 显式勾选，Enter 继续，不默认选首项；n／p 翻页、/ 搜索、s 回查已选，Esc／Ctrl-C 取消。稳定 ID 保留跨页／跨搜索选择，最多 100 项；请求取消和轮次 ID 阻止过期结果覆盖新页面。界面走 stderr，远端控制字符被清理，中文按显示宽度截断。

go-runewidth v0.0.16 直接处理宽度；Lip Gloss v1.1.0 当前为传递依赖。三个模块根 LICENSE 均为 MIT，发布仍需保留依赖许可及版权；完整颜色／表格、持续菜单与完整表单按 P5 实施。PTY 验证证明本机终端协议行为，不能代替 Terminal／iTerm2／Windows 宿主验收。

通用 api 不受业务白名单或版本识别限制，支持任意方法、重复 query、自定义非认证头、原始 UTF-8 --data、流式普通文件 --input、multipart --upload／--form、--include 和原始响应。--json 不套业务 envelope；认证及 Host 仍受固定上下文管理。默认总预算 30 秒、响应上限 64 MiB，可显式调整；所有写方法遵循确认规则且不自动重放。

显式 --output FILE 不覆盖已有路径：同目录临时文件完整接收、同步和关闭后，用硬链接提交，传输期间其他进程创建目标也不会覆盖。失败、超限和取消清理临时文件；不支持所需语义的文件系统明确失败，不回退覆盖。目标目录必须存在，Windows 文件系统实际运行仍待验证。
